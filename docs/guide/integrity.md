# 読み取り結果について言えること

同じ曲が途切れずに聞こえても、そのデータをどのように確かめたかは音だけでは分からない。
PiCDPlayerが扱うplayback integrityは、読み取り結果とその根拠を対応付け、
観測できたことと未確認のことを説明するための考え方である。

## 成功と一致は、別の問いへの答え

readが成功すると、アプリケーションはPCMを受け取れる。しかし、成功という戻り値だけで
そのPCMが原盤の内容と一致するとは言えない。読み取り時に観測できた異常と、
得られたbytesを比較した結果を分けて扱う必要がある。

同じ位置を複数回読み、PCMが一致すれば「同じbytesを複数回得た」と言える。
driveのcacheが同じデータを返していた可能性までは排除できない。
PiCDPlayerのrepeatもこの範囲の観測であり、独立した物理再読込や完全復元を保証しない。

例えば同一区間でAというPCMを二度得た場合、比較した範囲が一致したことは確認できる。
しかし二度目もドライブが内部に保存していたAを返したなら、ディスクから独立に読めたかは分からない。
一致回数を増やすことだけでは、この疑問は解消しない。

一度目がA、二度目がBなら、まず分かるのは不一致があったことだけである。
後続の読み取りで一致する候補を得ても、その採用手順と、原盤の正解を確認したことは分ける。
現在のrepeatは一致条件を満たすPCMを採用し、未解決なら読み取り失敗として再生を停止する。
具体的な条件や上限は[機能設計](../design/functional-design.md)を参照する。

| 観測できたこと | そこからはまだ言えないこと |
|---|---|
| readが成功しPCMを受け取った | 原盤のPCMと一致する |
| 同一区間のPCMを複数回比較して一致した | drive cacheから独立した読み取りだった |
| cacheの影響を排除できたと仮定して、独立readが一致した | 原盤との照合を済ませた |
| 読み取りPCMが原盤と一致すると確認できた | 音声出力の経路でも値が変わっていない |

後ろの二行は区別すべき概念を示しており、現在のPiCDPlayerが確認済みという意味ではない。

## 不明を残すことにも意味がある

CLEANは利用できた観測で異常を認めなかったことを表す。比較をしたかどうかは
SINGLE_READやMULTIPLE_MATCHなどの根拠で別に示す。
C2情報を取得していない状態と、取得して異常を検出しなかった状態も同一にはしない。
UNKNOWNを残すことで、後から得た情報と区別できる。

これは単に慎重な表示にするためではない。「未確認」と「確認した結果、非対応」では、
次に行う調査が変わるからである。libraryが訂正処理を報告した場合も、その報告を記録し、
別の読み取り方式のretry回数や独立した一致確認と同じ数値には置き換えない。

## 読み取りの外側にも確認する境界がある

さらに、読み取りPCMが正しくても出力経路でvolume、DSP、resamplingが働く可能性がある。
原盤との一致と出力端子までのbit一致は別々に調べる。
「CDだから」「S/PDIFだから」という理由でBIT-PERFECTを表示しない。

再生が途切れず続くことも別の評価である。bufferを増やして音切れが減っても、
採用PCMの正しさを新しく検証したことにはならない。逆に、読み取りを丁寧に比較しても
出力への供給が間に合わなければ音は途切れる。連続性と読み取りの根拠をそれぞれ観測する。

## 根拠は、それを得た音声区間と一緒に扱う

表示する時刻にも注意が必要である。最新readは先読み区間の結果であり、今聞こえる区間とは
異なり得る。そのため採用したPCMと根拠を一緒に持ち、再生位置に対応する根拠を推定する。
表示を受け取れなかったことを「問題なし」と扱わないことも、この方針の一部である。

例えば再生位置より先で再読込が発生しても、その結果を今聞こえる区間の評価としては表示しない。
seek後には古い世代のPCMと根拠を無効化する。現在の診断画面が「最新read」と
「現在再生中のPCM」を分けるのは、この取り違えを避けるためである。
原盤と照合した範囲がないのに、一曲全体を「検証済み」とすることも避ける。

現在の判定と公開値は[機能設計](../design/functional-design.md)と
[詳細設計](../design/detailed-design.md)を正とする。
C2、offset、cache対策、外部照合などの[未実装の要求](../design/integrity-design.md)は、
現在の保証に含めない。実機で言える範囲は[検証状況](../development/verification.md)を参照する。
