# 読み取り結果について言えること

readが成功すると、アプリケーションはPCMを受け取れる。しかし、成功という戻り値だけで
そのPCMが原盤の内容と一致するとは言えない。読み取り時に観測できた異常と、
得られたbytesを比較した結果を分けて扱う必要がある。

同じ位置を複数回読み、PCMが一致すれば「同じbytesを複数回得た」と言える。
driveのcacheが同じデータを返していた可能性までは排除できない。
PiCDPlayerのrepeatもこの範囲の観測であり、独立した物理再読込や完全復元を保証しない。

CLEANは利用できた観測で異常を認めなかったことを表す。比較をしたかどうかは
SINGLE_READやMULTIPLE_MATCHなどの根拠で別に示す。
C2情報を取得していない状態と、取得して異常を検出しなかった状態も同一にはしない。
UNKNOWNを残すことで、後から得た情報と区別できる。

さらに、読み取りPCMが正しくても出力経路でvolume、DSP、resamplingが働く可能性がある。
原盤との一致と出力端子までのbit一致は別々に調べる。
「CDだから」「S/PDIFだから」という理由でBIT-PERFECTを表示しない。

表示する時刻にも注意が必要である。最新readは先読み区間の結果であり、今聞こえる区間とは
異なり得る。そのため採用したPCMと根拠を一緒に持ち、再生位置に対応する根拠を推定する。
表示を受け取れなかったことを「問題なし」と扱わないことも、この方針の一部である。

現在の判定と公開値は[機能設計](../design/functional-design.md)と
[詳細設計](../design/detailed-design.md)を正とする。
C2、offset、cache対策、外部照合などの[将来案](../development/integrity-design.md)は、
現在の保証に含めない。実機で言える範囲は[検証状況](../development/verification.md)を参照する。
