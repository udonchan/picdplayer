# ドキュメント索引

現行設計は以下の3文書に集約する。機能ごとに同じ仕様を繰り返さず、
基本設計は責務とライフサイクル、機能設計は利用者に見える動作、詳細設計は関数と処理経路を扱う。
2026-09-17の実装（9d54547時点）を基準に整理した。将来構想と未検証事項は実装済みの保証から分ける。

| 文書 | 読む目的 |
|---|---|
| [ビルド手順](build.md) | 依存パッケージ、任意機能、手動起動 |
| [基本設計](basic-design.md) | 目的、要求、ブロック図、状態所有、ライフサイクル |
| [機能設計](functional-design.md) | 再生・CEC・metadata・APIの仕様、技術選定と制約 |
| [詳細設計](detailed-design.md) | 関数・型の責務、スレッド境界、処理順序、エラー経路 |
| [読み取り信頼性の拡張設計案](integrity-design.md) | 未実装・レビュー待ち。観測、検証、採用理由、UI protocol、段階的移行 |
| [操作・診断](operations.md) | CLI・HTTPの実行例、ログの見方 |
| [systemd運用](systemd.md) | インストール、権限、設定、起動・停止 |
| [検証状況と残課題](verification.md) | 自動試験、実機確認済み範囲、未確認事項 |
| [履歴索引](history/README.md) | 過去の設計比較、PoC、障害調査、実機結果 |

ソースへの相対リンクを詳細設計に置く。細かな宣言はヘッダーを参照し、設計書では呼び出し条件・
所有権・失敗時の扱いを記す。実装変更時は該当する設計書と検証状況を更新する。
過去の文書は履歴として保持し、現行仕様の追記先にしない。

拡張設計案は現行実装と区別する。読み取り信頼性の要件・モデル・phaseは上記の専用文書を正とし、
実装後に基本・機能・詳細設計の現行仕様と検証状況へ反映する。
